The GET API template

One read-only question solved in four steps: design it, code it, test it, then reuse the same shape for any other GET question.

The question

Build a read-only Product Catalog REST API.

  1. GET /api/v1/products/{id} returns one product, or 404 if it does not exist.
  2. GET /api/v1/products returns all products, with an optional category filter and pagination.
  3. Do not expose DB fields directly. Show inStock (true/false) instead of the raw stock count.
  4. Use Controller, Service, Repository and DTO layers.

Class design

  1. ClientGET /products/1Sends the request
  2. ControllerProductControllerHTTP only. No logic.
  3. ServiceProductServiceLogic, 404 decision, Entity to DTO
  4. RepositoryProductRepositoryQueries only
  5. Databaseproducts tableRows

Entity Product lives below the Service and never leaves it. DTO ProductResponse is what travels up to the Controller and out to the client. Each layer talks only to the layer directly below it.

Entity

mirrors the table
Product.java
@Entity
@Table(name = "products")
public class Product {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false)
    private String name;

    @Column(nullable = false)
    private String category;

    @Column(nullable = false)
    private BigDecimal price;

    private int stock;

    protected Product() {}      // JPA needs a no-arg constructor

    // getters only: a read-only API needs no setters
    public Long getId() { return id; }
    public String getName() { return name; }
    public String getCategory() { return category; }
    public BigDecimal getPrice() { return price; }
    public int getStock() { return stock; }
}

Service

logic + mapping
ProductService.java
@Service
public class ProductService {

    private final ProductRepository repo;

    public ProductService(ProductRepository repo) {
        this.repo = repo;
    }

    @Transactional(readOnly = true)
    public ProductResponse getById(Long id) {
        Product p = repo.findById(id)
                .orElseThrow(() -> new ResourceNotFoundException("Product not found with id: " + id));
        return toResponse(p);
    }

    @Transactional(readOnly = true)
    public Page<ProductResponse> getAll(String category, Pageable pageable) {
        Page<Product> page = (category == null || category.isBlank())
                ? repo.findAll(pageable)
                : repo.findByCategoryIgnoreCase(category, pageable);
        return page.map(this::toResponse);
    }

    private ProductResponse toResponse(Product p) {
        return new ProductResponse(p.getId(), p.getName(), p.getCategory(),
                p.getPrice(), p.getStock() > 0);
    }
}

Controller

HTTP only
ProductController.java
@RestController
@RequestMapping("/api/v1/products")
public class ProductController {

    private final ProductService service;

    public ProductController(ProductService service) {
        this.service = service;
    }

    @GetMapping("/{id}")
    public ProductResponse getById(@PathVariable Long id) {
        return service.getById(id);
    }

    @GetMapping
    public Page<ProductResponse> getAll(
            @RequestParam(required = false) String category,
            @PageableDefault(size = 10, sort = "id") Pageable pageable) {
        return service.getAll(category, pageable);
    }
}

Global exception handler

turns exceptions into 404 / 400
GlobalExceptionHandler.java
public record ApiError(int status, String message, Instant timestamp) {}

@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(ResourceNotFoundException.class)
    public ResponseEntity<ApiError> notFound(ResourceNotFoundException ex) {
        return ResponseEntity.status(HttpStatus.NOT_FOUND)
                .body(new ApiError(404, ex.getMessage(), Instant.now()));
    }

    // e.g. /products/abc (id is not a number)
    @ExceptionHandler(MethodArgumentTypeMismatchException.class)
    public ResponseEntity<ApiError> badType(MethodArgumentTypeMismatchException ex) {
        return ResponseEntity.badRequest()
                .body(new ApiError(400, "Invalid value for: " + ex.getName(), Instant.now()));
    }
}

Self-check before you say "done"

  • URL uses a plural noun and no verbs
  • Controller has no logic and returns a DTO, not the entity
  • Missing id gives 404 through the handler, not a 500 or null
  • List endpoints are paginated
  • IgnoreCase used where it makes sense
  • @Transactional(readOnly = true) on service reads

Follow-up questions to expect

Why not return the entity?
It hides internals, avoids lazy-load and recursion problems, and lets you shape the API contract separately from the DB.
What if there are 1 million products?
Pagination, an index on category, and a maximum page size.
The category filter is slow. What now?
Add an index: @Table(indexes = @Index(columnList = "category")).
How would you cache it?
@Cacheable("products") on getById, Redis in production, plus an eviction strategy.
No matches on the list endpoint: 404 or empty list?
Empty list with 200. An empty collection is still a valid result. 404 is for one specific missing resource.

The 5-minute recipe

  1. Write the entity from the table in the question.
  2. Write the response DTO: only the fields the client needs, plus any computed ones.
  3. Write the repository method for the query the question asks.
  4. Service: call the repo, throw ResourceNotFoundException if empty, map to the DTO.
  5. Controller: @GetMapping, pull the parameters, call the service, return the DTO.
